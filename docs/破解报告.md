## 二、最终算法

```
明文  p = <CRC8> * <版本> * <IP> * <PORT> + tail
置换  q = swap(p)                        # 互换 buf[i] 与 buf[half+i]，i 取 0,2,4,...
密文  c[0] = q[0] ^ ks[0]
      c[i] = q[i] ^ ks[i] ^ c[i-1]       (i >= 1)
输出  ServerData = Base64(c)
```

### 2.1 CRC8

| 参数 | 值 |
|---|---|
| 多项式 | `0xEDB88320`（反射 CRC-32） |
| init | `0xF0958FF3` |
| xorout | `0xFFFFFFFF` |
| 范围 | `<版本>` 起至明文结尾（含功能位） |
| 格式 | 小写十六进制 8 位 |

### 2.2 swap

```
half = n // 2
for i in 0, 2, 4, ... < half:
    swap(buf[i], buf[half + i])
```

自逆。这是此前"解码偶有单字符偏差"的真正原因：
加密读的是**置换后**的缓冲区，而内存里看到的那份明文始终是置换前的原样。

### 2.3 ks

只与 `n` 有关，与内容无关。`n = 52 + len(IP) + len(str(PORT))`（bit0 再 +18）。
45 种布局 × 两份长度族（60–72、78–90）实测完全一致，见 `ks_table.json`。

### 2.4 明文模板

```
<CRC8> * 36300 * <IP> * <PORT> * 0 * 0 * 0 * 0 * 0 * 0 * 0 * 0 * 00000000 * 0 * 0 * 0 * 0 * 0 *
```

开启 bit0（封包加密）时 tail 换成：

```
* 0 * 1 * 2671664405 * 2671664405 * 0 * 0 * 0 * 0 * 00000000 * 0 * 0 * 0 * 0 * 0 *
```

（`2671664405` 是官方工具写死的常量，与输入无关）

## 三、还原过程

### 3.1 静态分析：全部是死代码

`.text` 中 `0x8651e0`–`0x8657f0` 整段加密实现**零外部引用**，
连 `"ServerData"`、`"Login.ini"` 这两个字符串在 `.text` 里都没有引用点。
真正的加解密由 Enigma 虚拟化层执行，静态逆推走不通。

**但反汇编里留下了一条关键线索**：`swap(buf[i], buf[half+i])`，步长 2。
这条线索在后来成了决定性证据。

### 3.2 动态：内存高频轮询抓明文

对密文缓冲区以约 3 万次/秒轮询，抓到了明文被逐字节覆盖成密文的完整过程。
稳定抓到的明文形态是：

```
12345678*36300*127.0.0.2*2000*0*0*0*0*0*0*0*0*00000000*0*0*0*0*0*   ← 占位态
e4ba9d11*36300*127.0.0.2*2000*0*0*0*0*0*0*0*0*00000000*0*0*0*0*0*   ← 真实明文
```

第一行是占位（头部 `12345678`），第二行头部 `e4ba9d11` 才是真校验值。
这一步直接给出了 CRC 的**绝对真值**，是整个破解的转折点。

### 3.3 差分：不用 ks 也能定位结构

对两份同布局密文做 `d[i] = c[i] ^ c[i-1]` 再异或：

```
d1[i] ^ d2[i] = p1[i] ^ p2[i]
```

这是恒等式，不依赖密钥流。逐字符改动 IP/端口后发现：

| 改动 | 明文落点（n=65） |
|---|---|
| `ip[0]` | 15 |
| `ip[1]` | 48 |
| `ip[2]` | 17 |
| `port[0]` | 25 |
| `port[1]` | 58 |

即**奇偶分列**：偶数字符在 15,17,19,…，奇数字符在 48,50,52,…，
和反汇编里的 `swap(buf[i], buf[half+i])` 完全吻合。

### 3.4 CRC 辨识

有了绝对真值后，用**增量对齐**验证线性性：

```
cs(a) ^ cs(b) == crc32(msg_a) ^ crc32(msg_b)
```

假设成立 → 是标准反射 CRC-32。
再用 5 个不同长度（bodylen 53/57/59/62/64）的 `K(n) = cs ^ crc32(body)`
建立 `K(n) = M^n(D) ^ Y` 的线性方程组，GF(2) 高斯消元解出：

```
D = 0x0F6A700C  ->  INIT = 0xF0958FF3
Y = 0x00000000  ->  XOUT = 0xFFFFFFFF
```

6 个真值全部反算命中。

### 3.5 功能位

用 flags 单位样本（2/4/16/32/64/128）解码，差异位置直接暴露：

```
bit2  -> 段 8      bit4  -> 段 13     bit6  -> 段 15
bit1  -> 段 7      bit5  -> 段 14     bit7  -> 段 16
```

bit0 不占段位，改为 tail 换长格式（+18）。
bit3 需要额外变档文件，官方工具拒绝在无文件时置位，只能写出标志位。

## 五、走过的弯路（避免重复踩）

1. **先假设整个 `ip*port` 被转置**，直接把解析改成奇偶交织 —— 失败。
   原因：`ks` 是按"未置换的模板"标定的，置换在 `ks` 之前发生。
   正确顺序是 **先 `swap` 再 `XOR` 链**，所以解密必须 **先反链再 `swap`**。
2. **拿密文直接做 `unswap`** —— 顺序反了，得不到有效结果。
3. **用绝对值拟合 CRC**：`crc32(body)` 与真值差一个常量 `K`，
   而 `K` 随长度变，所以先入为主地找"某个 init/xorout 组合能直接对上"必然失败；
   换成**差分/增量**思路后一次命中。
4. **依赖内存抓到的第一份明文**：那是占位态（头部 `12345678`），
   用于标定会污染整条密钥流。
